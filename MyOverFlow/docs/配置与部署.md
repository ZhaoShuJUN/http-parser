# 配置、部署与协议范围

## 使用原 INI 配置

产品继续通过 `QAppCfgInfo` 读取 `configInfo.ini`。新增配置写入原文件的扩展分组；未知分组/键会保留，已知配置原子保存，格式错误不会悄悄回退到寄存器 0。界面保存后重启生效，不对采集中的串口或配置快照作半途修改。

### 原分组

| 分组/键 | 本版含义 |
|---|---|
| UserItfCfg/StyleType | 保留原键；当前主窗口按用户要求采用 HMI 深绿色样式 |
| UartCfg/UartNumb | 1～8 条总线 |
| UartPort1..8 / UartBaud1..8 | Linux TTY 路径及波特率 |
| UartEffe1..8 | 0 无校验、1 奇校验、2 偶校验 |
| UartStop1..8 | 保留旧配置编码：0 表示 1 停止位、2 表示 2 停止位；Linux 产品路径不支持 1.5 位 |
| DeviceCfg/DeviceHaveNumb | 测点数量，1～200，不是 Modbus 最大从站地址 |
| DevicePortN | 0 起始的串口数组索引 |
| DeviceAddrN | Modbus 从站地址 1～247 |
| DeviceRegStartN | 零基起始寄存器，按本次需求默认 0 |
| DeviceRegEndN | 沿用旧键名，保存的是读取数量，不是结束地址；数量由本版 Format 推导，u16/s16 为1，32位类型为2 |
| RecordFileInfo | 保留原分组；本版实际报警和视频路径见 Monitor、Recording |
| ReportCfg | 原有自定义键保留；本版传感器缓存自动生成遥测/遥信索引，MQTT 属性在 SensorN 配置 |

串口使用 8 数据位。TimeoutMsN（默认500）和 RetriesN（默认2）位于 UartCfg。八条总线分别工作，同一总线一次只允许一个请求；每个总线内多个测点轮询，总线带宽、等待和重试会影响实际周期。

### Sensor1..Sensor200

| 参数 | 含义 |
|---|---|
| Id / Name / Category / Unit | 唯一标识、名称、HMI 分类、实际单位 |
| Format | u16 / s16 / u32 / s32 / f32 |
| WordOrder | 32位 ABCD / CDAB / BADC / DCBA；单寄存器按 Modbus 大端读取 |
| Scale / Offset | 测量值 = 解码后的原值 × 倍率 + 偏移 |
| Low / High / Hysteresis | 下限、上限、恢复回差 |
| IntervalMs | 最短再次采样间隔，至少100 ms；并非无视总线负载的硬实时承诺 |
| Camera / Preset | 联动摄像头索引0～7（-1不联动）及预置位1～300 |
| LocalId | 沿用4G示例的设备本地标识，如 th_1、wl_1、gas_1、smoke_1 |
| DeviceId / NodeId | 可留空按原映射生成，也可填写平台正式指定编号 |
| ValueKey / AlarmKey / ServiceId | 上报属性及服务名，默认 value / alarm / analog |
| Calibrated | 实际数据类型、倍率、单位和阈值确认后设 true；只是确认标志，不是自动标定功能 |

访问均使用 0x03。标准 Modbus-RTU **不规定**温度/湿度/SF6/液位/烟雾浓度的数值类型、倍率、单位或厂家属性码。本次用户只确认了 0x03、寄存器从0开始和地址可设置，因此默认按原始值显示并标记未标定。不能擅自推断温度乘0.1、SF6为ppm或烟雾为某浓度单位。一个温湿度设备若温度/湿度分别在0和1寄存器，应按厂家寄存器表配置两个测点并共享从站/总线。

软件里的从站地址是**访问目标**；不会通过未经提供的厂商私有寄存器改写传感器自身的硬件地址。

阈值例：High=40、Hysteresis=2，值>40触发高限，回到<=38解除。Low同理。通信失败或非法解码标为offline，报警状态置位；无有效值上报null，不用0掩盖故障。

## RK3399 与八路硬件

1. 先确认 Linux/根文件系统是 aarch64 还是 armhf，以及厂家 Qt Kit 的 ABI。RK3399 能力不代表实际镜像一定为64位。
2. 用 dmesg、lsusb、/dev/serial/by-id 等确认设备驱动实际提供8个TTY。CH438通常是多串口扩展芯片，若整板经USB桥接，实际驱动由整板桥接方案决定，用户态Qt程序不能替代内核驱动。
3. 根据硬件确认TTL/RS232/RS485。RS485方向必须由适配器自动控制或正确的驱动完成；不能假定任意USB转串口都支持TIOCSRS485。
4. 确保运行账户有串口、配置文件、dataDir及录像盘权限。推荐稳定的udev别名，避免插拔后ttyUSB编号变化。
5. Qt显示后端由板厂镜像决定：X11、Wayland或EGLFS需匹配实际驱动。需要软键盘时安装对应Qt插件后设置QT_IM_MODULE=qtvirtualkeyboard，本版不强制启用缺失的插件。

交叉编译示例（路径需替换）：

```sh
QMAKE=/vendor-sdk/qt5/bin/qmake BUILD_DIR="$PWD/build-rk3399" ./scripts/build.sh
file build-rk3399/MyOverFlow
```

必须在目标SDK中准备相同ABI的Qt及libmosquitto。若SDK的qmake已正确设置sysroot，头文件和库放入该sysroot的标准路径；特殊路径可向qmake传入 `INCLUDEPATH+=...`、`LIBS+=-L...`。不能拿Windows MinGW/MSVC库或本次x86构建库冒充ARM依赖。板卡未提供SDK，因此本次没有声称完成目标ABI交叉编译。

依赖最低版本：Qt5.12+、C++17编译器、libmosquitto1.6+、FFmpeg5+。实际验证使用Qt5.15.15、libmosquitto2.0.21及当前FFmpeg。旧FFmpeg的RTSP参数可能仅支持-stimeout，不能直接使用该旧版；本工程已验证-rtsp_transport tcp和-timeout。

## 内存、线程与报警数据库

- QextSerialComm/QSerialPort在对应总线线程内构造和销毁。原指针信号接口保留，但新采集使用Polling，不将临时裸指针跨线程传递。
- QObject1CommIntf用互斥队列接收采样，原CCoreLogic执行解码与阈值判断；UI和MQTT取得同一份有锁快照。
- 原m_AllMeasVal/m_AllLetterVal、Report数组继续由核心同步；它们是旧整数兼容视图，小数测量值以缓存double为准。调用者不能绕过锁读写旧数组。
- 每个状态变化写一次报警记录，避免同一报警按采样周期重复插入；恢复和通信故障也有记录。
- SQLite位于 `[Monitor] DataDir` 下的alarms.sqlite，模拟用demo-alarms.sqlite；WAL、FULL同步，UI筛选后显示最近500条，API最多5000条。
- 数据库连接在创建它的主线程使用，核心线程通过排队信号写入。锁冲突等待100 ms后进入有界待写队列，每2秒重试，最多4096条。
- 无法写盘、持续队列溢出、断电时尚未提交的事件可能丢失；这不是工业安全系统的零丢失保障。历史数据库暂不自动删除，需要现场安排备份/归档。
- 备份运行中的WAL数据库应使用SQLite在线备份，不能只复制主文件忽略WAL。

Modbus RTU没有事务编号，超时隔离和CRC不能区分无限迟到的同地址同功能旧响应。按设备手册设置最大响应时间；本工程对短暂超时重试及一路故障隔离做了模拟测试，不替代电磁干扰/电气验收。

## 与4G示例相同的MQTT流程

真实链接libmosquitto，产品没有使用mock库。Qt HTTP只用于原网关鉴权：

1. POST authUrl，默认路径 `/iot/devices/auth/gateway`。body为gatewaySN、algId=0、checkID及devInfo，字段沿用上传示例。
2. 获取gatewayId及protocol=mqtt/mqtts的addr；缺失时沿用鉴权主机1906端口的旧回退逻辑。
3. MQTT3.1.1、Clean Session、Client ID=gatewayId，不retain。
4. 先发 `/v1/devices/{gatewayId}/topo/add`：`{"deviceInfo":[...]}`。
5. 再发 `/v1/devices/{gatewayId}/datas`：`{"devices":[{"deviceId":...,"serviceId":...,"data":[{...}],"eventTime":"yyyyMMddTHHmmssZ"}]}`。

类型映射沿用原表：th_→0001、wl_→0010、gas_→0002、smoke_→0008等；设备号为 `INH+4位类型+5位序号`，nodeId为`1511+deviceId+gatewaySN`。没有正式类型映射的pm_/sound_等沿用`L+LocalId`与LocalId回退。不是自动给SF6物模型发明正式编码；上线须由平台方确认gas_类型是否适用，也可显式填DeviceId/NodeId。

拓扑按约3800字节拆包；数据包含ValueKey指定值、AlarmKey指定报警、valid/state/sampleTime。原4G示例转发MCU数据属性，未提供完整正式物模型，因此流程、主题、外层字段及原编号规则已对齐，具体业务属性是否被云端接受仍需实际物模型确认。

QoS1收到匹配发布回调后出队，QoS0回调只表示本地网络写出；两者都不等于云端数据库成功入库。最多保留48个已排队数据批次，重连保留这些待发项并先重注册拓扑。离线期间采集仍更新内存，重连后会取得最新快照；这不是完整历史测量数据离线补传或断电缓存。报警历史保存在本地SQLite。

checkIdEnv/passwordEnv填写环境变量名称，不填写密码本身。TLS使用libmosquitto信任链和主机名验证；有自建CA时填caFile。mqtts发现结果会启用TLS，未关闭证书验证。原服务若使用明文HTTP，checkID仍按原接口传输，应由现场网络/平台选择其支持的HTTPS或专网。

4G模块的APN、SIM、拨号与厂商进程由设备系统管理，Qt程序使用已经建立的IP路由，不替换模块拨号软件。

## 海康摄像头与循环录像

按DS-2SC3Q140LY-TE常见海康网络接口设计，固件与权限仍需实机确认：

- CameraCfg/Count最多8。每个CameraN配置Enabled、Name、Rtsp、Isapi、User、PasswordEnv、PtzChannel及ChannelId。
- RTSP示例 `rtsp://IP:554/Streaming/Channels/101`；子码流通常为102。不要把密码写进URL，密码通过环境变量传入。
- ISAPI云台路径 `/ISAPI/PTZCtrl/channels/{PtzChannel}/continuous`、`/presets/{n}`、`/presets/{n}/goto`，支持HTTP Basic/Digest认证。
- PTZ通道通常为1，与GB20位ChannelId不同。方向/缩放松开发停止，另有700 ms停止保险。
- 选择一路预览；切换或停止会停止旧预览，不影响其他后台录像。可选GStreamer接口从HMI迁移，板厂MPP插件的实际选择/硬解性能需上板确认。

Recording分组：enabled、directory（绝对路径）、requireMount、maxGiB、reserveMiB、segmentSeconds、ffmpeg。目录必须先创建并挂载硬盘，默认requireMount=true，拒绝硬盘未挂载时写入系统根分区。

全部enabled摄像头独立FFmpeg拉取RTSP/TCP并以`-c copy`直存MKV，不在CPU上同时解码8路录像。每路文件位于 `directory/MyOverFlow/cameraN/mo_UTC时间_序号.mkv`。分段在关键帧处完成，不保证精确到秒。正常退出尽量写完当前容器，异常断电仍可能损坏最后分段。

3秒检查一次总配额和剩余空间，只删除本程序命名下的旧文件，保留每路最新两段（含活动文件）；不会回收其他命名文件或指向管理目录外的链接。旧片不足以回收时暂停录像。文件系统硬配额/严格保留天数需另行配置，当前按空间循环，不自动永久锁定报警录像。

界面有本地录像回放、时间进度及CSV报警导出。多个测点联动同一摄像头时，后到预置位命令会覆盖先前命令；复杂联动优先级需按现场规则继续扩展。

容量例：8路×4 Mbps约32 Mbps、约346 GB/日，尚未计额外开销；GB点播和本地预览还会建立额外拉流会话。确认摄像头并发会话数、交换机/硬盘带宽及RK3399散热条件。当前只做低分辨率功能联测，不是8路高清压力验收。

凭据不写入工程配置值，但当前FFmpeg需在子进程参数传递带认证的RTSP URL，同UID/特权用户可检查进程参数。生产设备应限制运行账户与进程可见性；程序不主动输出原始RTSP地址或FFmpeg完整错误文本。

## GB28181和国网接入边界

当前设备作为一个GB节点，下挂最多8个摄像头通道。配置在原INI的GB28181分组及CameraN/ChannelId中：

| 参数 | 用途 |
|---|---|
| enabled / version | 开关；当前实现仅2016，拒绝伪装为2022安全扩展 |
| charset | GB2312（默认）或UTF-8，按声明编码中文XML |
| deviceId / serverId / domain | 本机20位编码、平台20位编码、SIP域 |
| serverAddress / serverPort | 平台IPv4与SIP/UDP端口 |
| localAddress / localPort | 平台可达的本机IPv4和SIP端口 |
| passwordEnv | SIP密码环境变量名 |
| expires / heartbeatSeconds | 注册请求有效期与心跳周期；续注册遵从平台实际授予的Expires |
| fps | GB媒体固定帧率，必须与摄像头配置一致 |
| CameraN/ChannelId | 每个摄像头唯一20位通道编号，由平台方正式分配 |

实现REGISTER、MD5 Digest（含qop=auth）、注册续期、心跳、Catalog/DeviceInfo/DeviceStatus、基础PTZ DeviceControl、INVITE/ACK/BYE、有限重传及重复请求处理。连续心跳无响应会进入重新注册。SIP只接收配置的平台地址/端口。

实时媒体支持SDP `s=Play`、`RTP/AVP`、`PS/90000`和y=SSRC。ACK后启动对应摄像头拉流，H.264 Annex B访问单元封装PS（系统头/PSM/CRC/PES/PTS）再分片RTP/UDP；不同点播会话按通道与SSRC区分，BYE停止。

**GB源流必须为常规H.264、固定帧率且无B帧**，fps与设备实际一致。建议关闭H.265/H.265+、H.264+等智能编码并选择兼容配置。当前不保留RTSP原始PTS/DTS，按固定帧率生成90 kHz时间戳，不支持可变帧率或B帧精确重排；GB仅转发视频，音频未实现。

未实现：SIP/TCP、RTP/TCP主被动、NAT穿越、GB2022安全扩展/证书/国密、级联、GB历史录像检索回放、对讲、GB报警订阅/Notify、国网私有扩展。本地录像回放与GB历史回放是不同能力，不能混称已支持。

国网平台方仍须提供：适用GB版本及企标、平台地址/端口/域/分配编码、信令和媒体UDP/TCP要求、安全认证或国密、网络隔离与防火墙策略、码流参数，以及目录/心跳/点播/云台/录像/报警验收用例。只有“国网服务器”这一描述不足以确认全部接入规范；不能仅填IP就宣称已经符合国网完整规范。

## 上板验收

1. 核对ABI、Qt Kit、TTY驱动、串口电气层及方向控制，逐台校准实际寄存器值。
2. 验证阈值、回差、离线/恢复、SQLite查询及配置重启生效。
3. 逐台海康实机验证RTSP、ISAPI权限、云台方向和预置位位置，再验报警联动。
4. 真实硬盘上验证全部分段播放、空间回收范围、拔盘重挂、低空间暂停和掉电恢复。
5. 正式MQTT平台核对网关、编号、拓扑、业务属性和断网重连。
6. 按国网提供的接入规范逐项验收；若强制TCP/2022/国密或私有扩展，取得规范后补开发。
7. 在目标分辨率、码率与环境温度下进行24～72小时压力试验，记录采样延迟、CPU、内存、磁盘和视频丢帧，再决定投产。

凭据变量名称模板见根目录config-credentials.env.example。填写后保存到源码外的安全位置，通过系统进程环境或systemd EnvironmentFile注入；scripts/run.sh不会自动读取该模板。中文界面还需板端可用的中文字体。正式服务自动启动、显示会话和账户权限应在终端上板验证后按设备镜像配置。

从旧版七列alarms表升级时，会保留历史并补齐名称列；其他不兼容表结构会在初始化阶段报错，不会静默清空数据库。若将源码覆盖到旧目录，请先备份自有修改，并删除源根目录旧的ui_mainwindow.h/ui_dialogconfigdev.h后重新qmake，避免旧生成文件遮蔽新UI。推荐在单独构建目录编译。
