# 部署、参数与协议范围

## 1. 架构与迁移

原工程的界面、配置、通信、逻辑分层思路保留；原串口发送空实现、全局共享无锁缓冲区和平台专用二进制依赖不再参与产品构建。`legacy/` 可逐项对照原始文件。

产品源码：

| 文件 | 职责 |
|---|---|
| config | 加载、校验配置，引用环境变量中的凭据 |
| modbus | 每总线一个异步调度器；读请求、CRC、分包、超时重试 |
| store | 最新状态缓存、阈值与恢复、SQLite 报警及查询 |
| mqtt | HTTP 鉴权、MQTT 3.1.1 发布与心跳、重连 |
| camera | ISAPI 控制、FFmpeg 录像、磁盘回收 |
| gb28181 | SIP 信令、XML 查询、H.264 PS/RTP 媒体 |
| mainwindow | 数据显示、报警查询、配置、单路视频与云台操作 |

Qt 事件循环拥有缓存和串口对象，避免跨线程直接操作 UI；录像、GB 拉流分别使用子进程，UI 不解码 8 路录像。SQLite 使用短暂的 100 ms busy timeout，锁冲突时排队重试，避免长时间阻塞采集。

## 2. RK3399 构建与启动

推荐 Qt 5.12～5.15，Widgets、Network、Sql（QSQLITE 插件）、SerialPort、Multimedia、MultimediaWidgets，C++17 编译器，FFmpeg/FFprobe。RK3399 虽为 ARMv8，实际系统可能为 aarch64 或 armhf；必须以板卡系统、SDK 和 Qt Kit 的 ABI 为准。

板端原生编译可运行 `scripts/build.sh`；交叉编译用板厂 SDK 中已配置 sysroot 和目标 mkspec 的 Qt qmake，例如：

```sh
QMAKE=/your/vendor-sdk/qt5/bin/qmake BUILD_DIR="$PWD/build-rk3399" ./scripts/build.sh
file build-rk3399/MyOverFlow
```

路径是占位示例，不代表厂家 SDK 的实际名称。只指定 `aarch64-linux-gnu-g++`、却链接 x86 Qt 库，不能生成可用目标程序。不要复制上传项目的 MinGW/MSVC DLL 到 Linux 板卡。

启动前确保：

1. 程序用户对串口拥有读写权限，对配置文件/数据目录有写权限，对外接录像磁盘有写权限。
2. X11、Wayland 或 EGLFS 选择与实际 Qt 插件及板厂显示栈匹配。EGLFS 应在无其他 DRM 占用的环境启动；本工程未替用户固定板厂图形后端。
3. 板端 Qt Multimedia/GStreamer 能拉取并解码 RTSP H.264。RK MPP 硬解插件取决于板厂固件，工程不包含未经适配的 MPP 库。单路软件解码也需评估分辨率/CPU。
4. 系统时间同步，SQLite 存储介质可靠，磁盘正常挂载。录像日期使用 UTC。
5. 程序通过数据目录下的 QLockFile 拒绝重复实例（演示/真实模式分别加锁），同一硬件配置请始终使用同一数据目录；可通过 systemd 服务管理重启，GUI 服务需设置正确的显示会话。GUI 进程与采集共同运行，不能在关闭界面后继续假定后台采集仍在运行。

## 3. 串口及五类传感器

`ports` 最多 8 项，每项：

| 参数 | 含义 |
|---|---|
| device | 实际 Linux TTY 路径，推荐稳定的 `/dev/serial/by-id/...` 或 udev 别名 |
| baud/parity/stopBits | 波特率、N/E/O、1/2 停止位；数据位固定 8 |
| timeoutMs/retries | 响应超时（至少 50 ms）及额外重试次数（0～5） |

先检查 `dmesg`、`lsusb` 和 `/dev/tty*`，确认板端驱动实际提供 8 路 TTY。CH438 通常是多串口扩展芯片，若经板载桥接接入 USB，实际 USB 设备及驱动由整板方案决定；Qt 用户态代码不能替代内核驱动。根据硬件连接确定是 TTL、RS232 还是 RS485。RS485 半双工方向必须由适配器自动控制或驱动正确配置；本工程未假定任意 USB 串口都支持 `TIOCSRS485`。

`sensors` 各项：

| 参数 | 含义 |
|---|---|
| id/name/unit | 唯一标识、名称与显示单位 |
| port | `ports` 数组的 0 基索引 |
| slave | 软件访问的 Modbus 从站地址，1～247；不是给传感器改地址的私有写命令 |
| function/register | 用户要求为 `3` 与 `0`；寄存器地址零基，勿填文档的 40001 展示编号 |
| format | `u16`、`s16` 占 1 寄存器；`u32`、`s32`、`f32` 占 2 寄存器 |
| wordOrder | 32 位 ABCD / CDAB / BADC / DCBA；16 位寄存器按 Modbus 大端读取 |
| scale/offset | 实际值 = 解码原始值 × scale + offset |
| low/high/hysteresis | 低/高限与恢复回差，低于下限或高于上限报警；回差不得超过量程的一半 |
| intervalMs | 每个传感器的最短再次采样间隔，至少 100 ms；总线带宽/重试会延长实际周期 |
| camera/preset | 联动摄像头 0～7（-1 不联动）及预置位 1～300 |
| deviceId/nodeId | 云平台正式分配/约定的子设备编号与拓扑节点号 |
| valueKey/alarmKey/serviceId | 可选，上报数值字段、报警字段与服务标识，默认 value/alarm/analog |

五类默认配置：温度、湿度、液位、SF6、烟雾浓度；都从寄存器 0 开始读 0x03，示例从站为 1～5，默认都在第 0 条总线。其余 7 路可配置更多设备。**标准 Modbus-RTU 不定义厂家数值类型、倍率或测量单位，不能仅由“标准协议”推断温度为 0.1 ℃或 SF6 为 ppm。默认 u16/倍率 1、阈值及未确认单位是可运行的配置模板，不是现场标定。**

如果同一物理温湿度传感器的温度和湿度分别位于寄存器 0/1，应配置两个测点并共享 port/slave，寄存器分别填 0/1；必须与实际寄存器表一致。

每条总线同一时间仅一个未完成请求，校验从站、功能、长度和 CRC；失败重试后将测点标为 offline。超时后的隔离间隔减小迟到帧误配风险，但 Modbus RTU 没有事务编号，不能完全辨别无限迟到的同地址同功能旧响应，应按传感器最大响应时间设定 timeoutMs。

## 4. 报警、数据库与数据寿命

`dataDir/alarms.sqlite` 保存报警、正常恢复和通信异常状态变化；重复的同类报警不会每个采样周期重复插入。高限回差例：high=40、hysteresis=2，数值 >40 报警，恢复到 <=38 才解除。低限同理。界面使用缓存最新值；无有效数据上报 null，并保留 valid=false，避免将故障当作测量值 0。

数据库使用 WAL 和 FULL 同步；查询按时间与测点筛选，UI 最近 500 条，Store API 上限 5000。备份运行中的 WAL 数据库时必须使用 SQLite backup/在线备份工具，不能只复制主文件忽略 WAL。

数据库暂时不可写时，最多缓存 4096 条待写事件，每 2 秒重试。磁盘持续满/损坏、队列溢出和断电仍可能丢失尚未写入事件，界面及日志会显示异常；这不是工业安全系统的零丢失承诺。数据库历史暂不自动清除，应根据保存年限安排经过备份的归档。

同一摄像头由多个测点联动时，后到的报警预置位命令会覆盖先前命令；复杂优先级/排队策略应按现场联动规范扩展。所有启用摄像头始终录像，报警发生时调整预置位，事件时间可用来定位对应分段；程序没有把报警录像自动永久锁定以阻止循环覆盖。

## 5. MQTT 与 4G 模块兼容

沿用上传网关接口：

1. POST `authUrl`（路径 `/iot/devices/auth/gateway`），JSON 为 gatewaySN、algId=0、checkID、devInfo。
2. 校验 HTTP 200，读取 gatewayId，递归找到 protocol=mqtt 的 addr；缺失时用鉴权主机的 1906 端口。
3. MQTT 3.1.1、Clean Session、Client ID=gatewayId；先向 `/v1/devices/{gatewayId}/topo/add` 发布 `{"deviceInfo":[...]}`。
4. 再向 `/v1/devices/{gatewayId}/datas` 发布 `{"devices":[{"deviceId":...,"serviceId":...,"data":[{...}],"eventTime":"yyyyMMddTHHmmssZ"}]}`。

子设备注册字段沿用 nodeId/name/description/manufacturerId/model。每 8 个设备拆一条；上报 data 内含 value（或 valueKey 指定名称）、alarm（或 alarmKey）、sensorId、valid、state、unit、sampleTime。原 4G 网关只是转发 MCU 数据属性，尚无正式物模型文档；**外层协议与流程已对齐，具体数据属性/编号是否被正式云平台接受仍需物模型确认。** 不将传感器报警变量映射到未经提供的正式属性编码。

原示例按 INH 类型与网关 SN 生成设备编码。本工程要求显式配置正式 deviceId/nodeId，避免把 SF6 或烟雾浓度擅自注册成错误物模型。参考映射和原生成逻辑在 `reference/gateway-source/src/main.c`，可与平台商共同确认后填写。

`mqtt.qos=1` 为默认，收到匹配 PUBACK 后处理下一条；`qos=0` 行为近似参考程序默认，只确认本地排队写出，不能说明 Broker 收到。两种模式均不代表云端应用数据库成功入库。断线后重新 HTTP 鉴权、注册拓扑，然后上报最新缓存快照；**不是离线全量历史补传**。历史测量数据只存内存；报警事件存 SQLite。当前没有向未提供的下行 Topic 订阅或远程配置命令。

`mqtts://` 地址或 `tls=true` 使用 QSslSocket 和系统信任根，保持证书/主机名验证；不调用 ignoreSslErrors。原服务器为明文 HTTP 时，checkID 会按原协议明文传输，应在现场专网或服务端支持的 HTTPS 下使用。使用自签 CA 时按目标系统的受支持信任机制安装 CA。

4G 拨号、APN、SIM 和厂商 `4g_server` 管理由操作系统/模块程序负责，本 Qt 应用直接使用板端 IP 路由；程序没有把 RK3399 假定为 GC6511，也不覆盖模块的拨号配置。

## 6. 海康摄像头与录像

配置面向海康 DS-2SC3Q140LY-TE 的常见 RTSP/ISAPI 接口，实际固件能力与权限须上机核实：

- 直连摄像头主码流示例 `rtsp://IP:554/Streaming/Channels/101`；子码流常用 102。地址只填写 URL，不在配置内嵌明文密码。
- `isapi` 为 `http(s)://IP[:port]`，云台通道 `channel` 常为 1，**不是 GB 20 位通道 ID**。
- 控制使用 `/ISAPI/PTZCtrl/channels/{channel}/continuous`、`/presets/{id}` 和 `/presets/{id}/goto`；支持 Basic/Digest HTTP 认证，校验 HTTP/海康状态码。
- 手动方向和缩放按下发送、松开发停止，并增加 700 ms 停止保险，防止丢失停止指令后持续转动。长距离运动可多次操作。
- 单选一路 Qt 视频预览；切换摄像头会停止旧预览，不影响 8 路后台录像。预览失败不会伪造视频画面。

启用 recording 后所有 enabled=true 摄像头独立拉流。FFmpeg `-c copy` 不转码，以 MKV 分段；segmentSeconds 默认 300，实际分段边界在关键帧处，摄像头 GOP 应设置合理。退出时发送 q 尽量写完容器尾部，再超时终止。断电可能使最后一个分段不完整，既有完成分段可独立播放。

录像路径 `directory/MyOverFlow/cameraN/mo_UTC时间_序号.mkv`，只回收该命名下的旧文件；每路保留最新两个分段（含写入中的文件），避免删除正在写入的视频。硬盘 quota `maxGiB` 与 `reserveMiB` 为清理触发条件，3 秒检查一次，需留足最多 8 路 × 两个分段及码率波动空间；无法回收则暂停录像。

`requireMount=true` 默认拒绝写在根文件系统；先挂载硬盘并创建 directory。测试机仅测试时允许 false。不要把录像子目录符号链接到管理根目录外。录像配额不是文件系统硬配额，严格容量约束还应在操作系统配置磁盘配额。

带宽/容量估算：8 路 × 4 Mbps ≈ 32 Mbps，约 346 GB/日（未含额外开销）；预览与 GB 点播会额外拉取码流，应核对摄像头并发会话数及交换机带宽。当前未做 RK3399 八路高清持续压力测试。

凭据通过 `passwordEnv` 指定的进程环境变量读取。FFmpeg 必须获得含认证的 RTSP 输入 URL，当前实现会在该子进程参数中传递，因此同 UID/特权用户可检查进程参数；生产机应限制 shell/进程可见权限，不向其他用户开放运行账户。程序日志不会主动输出完整 RTSP 地址或原始 FFmpeg 错误文本。

## 7. GB28181 与国网接入

当前实现：GB/T 28181-2016 常用 SIP/UDP 实时接入流程；设备作为 1 个平台下挂最多 8 个摄像头通道，由本机接入 RTSP 并 PS/RTP 转发。不是把网络摄像头直接 GB 注册能力伪装为本程序实现。

必填参数：设备编码 deviceId、平台编码 serverId（20 位）、域 domain（通常前 10 位）、serverAddress/serverPort、可达的本机 IPv4 localAddress/localPort、passwordEnv、expires、heartbeatSeconds。每个摄像头 channelId 必须唯一且为 20 位，并由平台管理员分配，示例编码不应直接用于生产。

媒体：平台 INVITE 中的 SDP 必须是 s=Play、RTP/AVP UDP、动态 PT 对应 PS/90000、y=十进制 SSRC；本机回复绑定的实际 UDP 源端口并在 ACK 后发送 PS/RTP，BYE 结束。SIP 请求/应答有有限重传及重复请求处理。仅接收配置的 SIP 服务器 IPv4 与端口。

**摄像头码流要求 H.264、固定帧率、无 B 帧，gb28181.fps 与摄像头实际设置一致；推荐关闭 H.265/H.265+、H.264+ 智能编码并选择常规 H.264 兼容配置。** 当前从 Annex B AUD 划分访问单元，以固定帧率生成 90 kHz PTS，不保留源 RTSP 时间戳，不能用于有 B 帧或可变帧率流的精准时间重排。GB 音频转发未实现，录像是否保存音频取决于源流。

当前未实现：SIP/TCP、RTP/TCP 主被动、NAT 穿越/公网映射、GB2022 安全扩展、证书/国密、级联、历史录像检索与回放、语音对讲、国网私有扩展。DeviceControl 实现基础 PTZ/预置位控制；没有宣称实现完整控制集。GB 报警 Notify/订阅未实现，传感器报警当前通过 MQTT 和本机联动处理。

国网接入必须由平台方确认以下表单，不应猜测服务器型号或规范：

| 需平台方提供 | 用途 |
|---|---|
| 适用 GB28181 版本、国网企标/地方接入规范 | 判断当前 2016 UDP 子集是否允许 |
| SIP 平台 IP、端口、域、平台注册编码及分配的设备/通道编码 | 注册和目录对应 |
| SIP UDP/TCP 及 RTP UDP/TCP 要求、网络与防火墙端口范围 | 确定信令/媒体传输方式 |
| 密码/证书/国密/专网隔离要求 | 决定认证能力与安全边界 |
| PS/H.264 码流、分辨率、帧率、GOP、音频、时间戳要求 | 决定媒体适配和容量 |
| 目录、云台、心跳、报警、录像回放和验收用例 | 确认功能闭环 |

如平台强制 TCP、2022/国密、历史回放或国网专有协议，须取得规范后继续开发相应模块；仅填写示例中的 version 或 IP 不能完成这些适配。配置校验会拒绝将当前实现声明为 2022。

## 8. 现场验收顺序

1. 确认 RK3399 ABI、Qt 插件/屏幕、8 个 TTY 和 RS485 电气连接；检查串口权限。
2. 逐个传感器对照厂家寄存器表、倍率、单位与标准表校准；再接入全部总线，测试断线、CRC 错误和响应超时。
3. 校验各阈值、回差、报警/恢复、SQLite 记录、CSV 查询和通信异常；短时锁库后确认待写记录恢复。
4. 逐个摄像头验证 RTSP 画面、ISAPI 权限、方向和预置位；验证报警联动选择正确通道。
5. 挂载真实硬盘，启用 8 路录像并验证分段播放、回收范围、低空间暂停、磁盘拔除/重挂和异常断电恢复。
6. 使用正式 MQTT 网关/物模型参数检查鉴权、拓扑、数值、报警和离线重连。确认平台是否接受 QoS1。
7. 按国网正式测试用例验证注册、目录、多个通道点播、SSRC、云台、BYE、平台重启/掉线等；补齐平台强制但本工程未覆盖的功能。
8. 在目标分辨率和码率下运行 24～72 小时，记录 CPU、内存、温度、磁盘、丢帧、串口采样延迟及网络恢复情况，再决定投产。

凭据名称模板见 `config/credentials.env.example`。将填写后的文件放在源码目录之外，限制读取权限，通过 systemd EnvironmentFile 或启动进程的导出变量注入。`scripts/run.sh` 不会自动读取该模板。`scripts/myoverflow.service.example` 是未在板卡上执行的部署模板，需修改账户、目录、显示后端及显示会话认证；先在终端完成实机验证再启用自动启动。
